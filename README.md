# Книжный клуб — Telegram Mini App

Каталог книг клуба, отзывы с оценкой 1–5 и даты встреч. Открывается прямо из группы в Telegram, без регистрации: пользователя отдаёт сам Telegram.

- **Бэкенд:** Go 1.24, только стандартная библиотека. Один бинарник, фронт вшит внутрь через `embed`.
- **Фронт:** HTML + JS + CSS без сборки. Крупный шрифт и кнопки, цвета из темы Telegram.
- **Данные:** один JSON-документ. В облаке это объект в бакете Object Storage, локально и на VPS — файл `data/bookclub.json`.
- **Фото обложек:** на Яндекс Диске владельца клуба, в папке приложения (см. «Фото обложек на Яндекс Диске»).
- **Хостинг:** Yandex Cloud Serverless Containers, укладывается в бесплатный объём (см. «Деплой в Yandex Cloud»).

## Что умеет

По умолчанию у всех участников одинаковые права. Если задать `ADMIN_IDS`, включается режим администрирования (см. «Настройка в Telegram», шаг 6).

- **Книги.** Добавить может любой: название, автор, ссылка, пара слов. Удалить можно свою книгу, администратор — любую.
- **Фото обложки.** Добавить при создании книги или потом на её странице: снять камерой или выбрать из галереи. Заменить или убрать фото может тот, кто добавил книгу, или администратор. Обложки видны в списке и на странице книги.
- **Поиск** по названию и автору. Регистр, «ё/е» и кавычки не важны, слова можно вводить в любом порядке: «булгаков мастер» найдёт «Мастер и Маргарита».
- **Отзывы.** Оценка 1–5 и текст по желанию. Одна книга — один отзыв, его можно изменить или удалить. Чужие отзывы удаляет только администратор.
- **Фото к отзыву.** Одно на отзыв: добавить, заменить или убрать может автор, убрать чужое — администратор. Видно всем под текстом отзыва. Хранится там же, где обложки.
- **Встречи.** Назначает, меняет и отменяет администратор, остальные видят расписание. Без администраторов это может любой участник.
- **Поделиться в группе.** Кнопкой на странице книги или под своим отзывом участник отправляет его в группу клуба от своего имени: оценка, текст и ссылка, которая открывает сразу эту книгу. Если у отзыва есть фото (а если нет — у книги есть обложка), под ссылкой в сообщении Telegram покажет это фото как превью.

## Запуск локально

```bash
DEV_MODE=1 go run ./cmd/bookclub
```

Откройте http://localhost:8080/?dev=1:Анна — вы участник Анна. Второй участник: http://localhost:8080/?dev=2:Маша (в другой вкладке).

Проверить режим администрирования: `DEV_MODE=1 ADMIN_IDS=1 go run ./cmd/bookclub` — Анна станет администратором, Маша останется обычным участником.

Фото обложек локально хранятся в папке: `DEV_MODE=1 COVERS_DIR=data/covers go run ./cmd/bookclub`. Без `COVERS_DIR` и `YADISK_TOKEN` кнопок фото нет.

`DEV_MODE=1` разрешает входить без Telegram под любым именем. **На сервере его не включать.**

```bash
go test -race ./...
```

## Структура

```
cmd/bookclub/        main: конфиг из env, сборка зависимостей, graceful shutdown
internal/auth/       проверка подписи initData (HMAC-SHA256 от токена бота)
internal/tg/         Bot API: членство в группе (getChatMember + кэш), посты в группу (sendMessage)
internal/store/      хранилище: всё в памяти; запись в файл или в бакет Object Storage
internal/covers/     фото обложек: Яндекс Диск (REST API) или локальная папка, кэш в памяти
deploy/              yandex-cloud.sh — деплой одной командой
internal/api/        HTTP: роуты, права, валидация, DTO
web/static/          фронт: index.html, app.js, style.css
```

## Настройка в Telegram

Нужен адрес с **HTTPS** — Telegram открывает Mini App только по https.

1. **Бот.** В @BotFather: `/newbot` → получите токен (`BOT_TOKEN`).
2. **Mini App.** Там же `/newapp` → выберите бота, укажите URL сервера и короткое имя, например `club`. Ссылка на приложение: `https://t.me/<имя_бота>/club`.
3. **Ссылка в группе.** Отправьте эту ссылку в группу клуба и закрепите. По нажатию приложение откроется внутри Telegram.
4. **Только для участников (рекомендую).** Приложение пускает тех, кто открыл его по ссылке **изнутри группы клуба**. Когда Mini App открывают по прямой ссылке, Telegram передаёт `chat_instance` — постоянный ID чата, из которого её открыли, одинаковый для всех в этом чате и подписанный Telegram. Ссылку в закрытой группе видят только участники, а пересланная в другой чат ссылка приходит с другим `chat_instance`. Bot API для этого не нужен.

   Как узнать `chat_instance` группы:
   - задеплойте без `CLUB_CHAT_INSTANCE` (пока приложение открыто всем);
   - откройте приложение по ссылке из группы клуба;
   - консоль Yandex Cloud → Serverless Containers → `bookclub` → Логи, найдите строку `opened from chat … chat_type=supergroup` (или `group`) и возьмите из неё `chat_instance`;
   - впишите его в `.env` как `CLUB_CHAT_INSTANCE=…` и задеплойте снова.

   После этого приложение не откроется из списка «недавних приложений» или по пересланной ссылке: только из группы. Чужие увидят просьбу открыть приложение из группы клуба.

   Есть и проверка через `getChatMember` (`CLUB_CHAT_ID`, ID группы `-100…` из `getUpdates`), она работает при любом способе открыть приложение. Но ей нужен доступ к `api.telegram.org`, а из Yandex Cloud он обычно закрыт (см. `TELEGRAM_API_URL`). Можно задать обе: сначала проверяется `chat_instance`, потом `getChatMember`.
5. **«Поделиться в группе».** Укажите ссылку из шага 2 в `MINIAPP_URL`. Тогда на странице книги и под своим отзывом появляются кнопки «Поделиться книгой в группе» и «Поделиться отзывом в группе». Кнопка открывает в Telegram выбор чата с готовым текстом, участник выбирает группу клуба и отправляет от своего имени. Сообщение отправляет телефон участника, а не сервер, поэтому это работает, даже когда из Yandex Cloud не открывается `api.telegram.org`. В сообщении ссылка, которая открывает приложение сразу на этой книге.

   **Фото в сообщении с отзывом.** Прикрепить фото к такому сообщению нельзя: `t.me/share/url` передаёт только текст и ссылку, а настоящее вложение умеет собрать только бот (`savePreparedInlineMessage`), которому нужен `api.telegram.org`. Поэтому, если у отзыва есть фото (или у книги обложка), первой ссылкой в сообщении идёт **публичная ссылка на это фото на Яндекс Диске** (`https://yadi.sk/i/…`): по ней Telegram показывает фото в превью. Ниже в тексте — «Открыть в приложении: https://t.me/…», по ней участники входят в приложение из группы, как раньше. Фото публикуется на Диске один раз — когда автор отзыва открывает страницу книги, — и ссылка сохраняется в данных клуба. Публичная ссылка открывает фото любому, у кого она есть. Если Диск откажется публиковать (например, токену не хватает прав), в логе будет `photo not published on Yandex Disk` с причиной, а отзыв уйдёт без превью, с обычной ссылкой на приложение. Без Диска (фото в `COVERS_DIR`) вместо ссылки Диска используется своя страничка сервера `/s/<токен>` с тегами Open Graph: она работает там, где робот Telegram достаёт до сервера (VPS за рубежом), но не в Yandex Cloud.

   Пример:

   ```
   ✍️ Мой отзыв на «Обломов» — Гончаров
   ★★★★☆ 4 из 5

   Неспешно, но здорово
   https://t.me/<имя_бота>/club?startapp=book_…
   ```

   Длинный текст обрезается до 1500 символов: слишком длинные ссылки обмена некоторые клиенты не открывают.

   Автоматические посты от имени бота тоже есть, но выключены по умолчанию, включаются `NOTIFY_GROUP=1`. Им нужен доступ сервера к Bot API, а из российских дата-центров он обычно закрыт (см. `TELEGRAM_API_URL`).
6. **Администраторы.** Укажите их Telegram ID в `ADMIN_IDS` — через запятую или пробел. Администратор удаляет любые книги и отзывы и единственный назначает, меняет и отменяет встречи. Внизу экрана у него написано «· администратор».

   Как узнать ID без логов: пока `ADMIN_IDS` пустой, внизу экрана приложения есть блок «Настройка клуба» с вашим Telegram ID и кнопкой «Скопировать». В логах сервера то же самое видно в строке `user seen id=… name=…`. Ещё вариант — бот @userinfobot в Telegram.

   Так же без логов находится и `chat_instance` для шага 4: пока не задан ни `CLUB_CHAT_INSTANCE`, ни `CLUB_CHAT_ID`, откройте приложение по ссылке из группы клуба — в блоке «Настройка клуба» появится его значение. Блок видят все участники, пока настройка не закончена; оба значения не секретные (ID свой, а `chat_instance` пускает только запросы, подписанные Telegram для этого чата). Когда заданы и доступ, и администраторы, блок пропадает.

   Права администратора проверяет сервер, кнопки на экране — только подсказка. Удаления чужих книг и отзывов пишутся в лог (`admin deleted book`, `admin deleted review`): видно, кто и что удалил.

## Фото обложек на Яндекс Диске

Фото лежат на вашем личном Яндекс Диске, в папке «Приложения/<название приложения>/covers». Приложению нужен OAuth-токен с доступом **только к своей папке**: остальной Диск ему не виден, и утёкший токен не откроет ваши файлы.

1. Зайдите в браузере в **свой** аккаунт Яндекса (тот, на чьём Диске будут фото).
2. Откройте https://oauth.yandex.ru/client/new и создайте приложение:
   - название — например, «Книжный клуб» (так будет называться папка на Диске);
   - платформа — «Веб-сервисы», Redirect URI — `https://oauth.yandex.ru/verification_code`;
   - доступы: «Яндекс Диск REST API» → **«Доступ к папке приложения на Диске»** (`cloud_api:disk.app_folder`). Больше ничего не отмечайте.
3. На странице приложения скопируйте ClientID и откройте `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`. Разрешите доступ — Яндекс покажет токен.
4. Впишите его в `.env`: `YADISK_TOKEN=y0_…` и задеплойте. В логах при старте будет `cover photos where="Yandex Disk app:/covers"`.

Токен действует долго (обычно год). Когда он истечёт или вы отзовёте доступ, загрузка и показ фото начнут падать с ошибкой в логах `Yandex Disk rejected YADISK_TOKEN` — получите новый токен по шагу 3. Книги и отзывы при этом работают как обычно.

Обложки занимают немного: телефон сжимает фото до 1280 px по длинной стороне, это 150–300 КБ. Тысяча книг — около 300 МБ из бесплатных 5 ГБ Диска. Удалённые и заменённые фото стираются с Диска сразу, мимо корзины.

## Переменные окружения

| Переменная | По умолчанию | |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота. Обязателен, если не `DEV_MODE=1` |
| `CLUB_CHAT_INSTANCE` | пусто | `chat_instance` группы клуба (см. «Настройка в Telegram», шаг 4). Задан — приложение открывается только по ссылке из группы. Можно несколько через запятую |
| `CLUB_CHAT_ID` | пусто | ID группы клуба для проверки через `getChatMember`. Нужен доступ к Bot API |
| `NOTIFY_GROUP` | `0` | `1` — бот сам пишет в группу о каждой новой книге и отзыве. Нужны `CLUB_CHAT_ID` и доступ к Bot API (`TELEGRAM_API_URL`) |
| `TELEGRAM_API_URL` | `https://api.telegram.org` | Адрес Bot API. Из российских дата-центров `api.telegram.org` с весны 2026 года часто недоступен — тогда здесь адрес своего обратного прокси за рубежом |
| `ADMIN_IDS` | пусто | Telegram ID администраторов через запятую или пробел. Пусто — администраторов нет, встречи назначает любой участник |
| `MINIAPP_URL` | пусто | Ссылка на приложение `https://t.me/<имя_бота>/club`. Нужна для кнопок «Поделиться в группе»: без неё кнопок нет |
| `PUBLIC_URL` | пусто | Свой https-адрес сервера без пути, например `https://bba….containers.yandexcloud.net`. Нужен для превью фото в сообщениях с отзывом, только если прокси меняет `Host`; пусто — адрес берётся из запроса |
| `DATA_BUCKET` | пусто | Бакет Object Storage. Задан — данные хранятся в нём, `DATA_FILE` не используется |
| `DATA_KEY` | `bookclub.json` | Имя объекта в бакете |
| `YC_IAM_TOKEN` | пусто | IAM-токен для запуска с бакетом на своей машине (`yc iam create-token`). В облаке токен берётся у сервисного аккаунта |
| `DATA_FILE` | `data/bookclub.json` | Файл с данными, если бакет не задан |
| `YADISK_TOKEN` | пусто | OAuth-токен Яндекс Диска для фото обложек (см. «Фото обложек на Яндекс Диске»). Пусто — фото выключены, если не задан `COVERS_DIR` |
| `YADISK_DIR` | `app:/covers` | Папка на Диске. `app:/…` — внутри папки приложения; `disk:/…` — где угодно, но тогда токену нужен доступ ко всему Диску |
| `COVERS_DIR` | пусто | Хранить фото в локальной папке вместо Диска: для разработки и своего сервера |
| `PORT` / `ADDR` | `:8080` | Порт задаёт Serverless Containers; `ADDR` важнее, если указан |
| `INITDATA_MAX_AGE` | `24h` | Сколько действует вход после открытия приложения |
| `DEV_MODE` | — | `1` = вход без Telegram, только для разработки |

## Деплой в Yandex Cloud

Приложение работает в Serverless Containers, данные лежат в бакете Object Storage. Адрес с HTTPS (`https://….containers.yandexcloud.net`) выдаётся сразу и открывается в России без VPN.

**Что нужно один раз**

1. Аккаунт в [консоли Yandex Cloud](https://console.yandex.cloud) и платёжный аккаунт с привязанной картой. Пробного периода для новых клиентов сейчас нет, но списывается только то, что вышло за бесплатный объём.
2. [yc CLI](https://yandex.cloud/ru/docs/cli/quickstart), затем `yc init` — выберите облако и каталог.
3. Запущенный Docker (Docker Desktop, OrbStack или Colima) и Go 1.24+.

**Деплой**

```bash
export BOT_TOKEN=123456:ABC...      # от @BotFather
export CLUB_CHAT_ID=-100...         # ID группы клуба, см. «Настройка в Telegram»
export MINIAPP_URL=https://t.me/<имя_бота>/club   # для кнопок «Поделиться в группе»
./deploy/yandex-cloud.sh
```

Каждый запуск заменяет переменные контейнера целиком: если забыть `export CLUB_CHAT_ID`, новая версия выйдет без проверки участников. Чтобы не экспортировать каждый раз, положите переменные в `.env` в корне проекта (он в `.gitignore`), скрипт прочитает его сам. Создать его проще всего так: `./deploy/setup-env.sh` — возьмёт токен из текущего контейнера (или спросит), найдёт ID группы через `getUpdates` и спросит короткое имя Mini App. Вручную `.env` выглядит так:

```
BOT_TOKEN=123456:ABC...
CLUB_CHAT_ID=-100...
MINIAPP_URL=https://t.me/<имя_бота>/club
YADISK_TOKEN=y0_...
```

Скрипт печатает адрес приложения. Его нужно указать в @BotFather (`/newapp`, а при смене адреса — `/myapps` → бот → Edit Web App URL). Повторный запуск выкатывает новую версию по тому же адресу.

Что создаёт скрипт (существующее переиспользует):

| Ресурс | Имя | Зачем |
|---|---|---|
| Сервисный аккаунт | `bookclub-runner` | От его имени контейнер скачивает образ (`cloud-registry.artifacts.puller`) и читает/пишет данные (`storage.uploader`, без права удалять) |
| Бакет | `bookclub-<id каталога>` | Данные: `bookclub.json` и ежедневные копии `backups/ГГГГ-ММ-ДД.json` |
| Docker-реестр | Cloud Registry | Образ приложения. Container Registry Яндекс закрывает 14 декабря 2026 года, поэтому сразу Cloud Registry |
| Контейнер | `bookclub` | 128 МБ, 1 vCPU, таймаут 30 с, до 4 запросов на экземпляр, открыт без авторизации |

**Сколько стоит.** Бесплатный объём в месяц: Serverless Containers — 1 млн вызовов, 10 ГБ×ч памяти и 5 vCPU×ч на обработку запросов; Object Storage — 1 ГБ, 10 000 записей, 100 000 чтений. Клубу этого хватает с большим запасом: приложение делает одну запись на каждое изменение и одну проверку бакета не чаще раза в 3 секунды. Вне бесплатного объёма остаются хранение образа в реестре (~10 МБ на версию) и логи сверх бесплатного объёма Cloud Logging; при таких размерах счёт должен быть символическим. Старые версии образа можно удалять в консоли реестра.

**Если что-то не так**

- *Образ не собирается.* Базовый образ берётся из `gcr.io`, Docker Hub не нужен. Если `gcr.io` недоступен, соберите с включённым VPN.
- *«Не получилось проверить участие в клубе… context deadline exceeded».* Сервер не может достучаться до `api.telegram.org`: из российских дата-центров, включая Yandex Cloud, Bot API режется. Нужен прокси за рубежом и `TELEGRAM_API_URL`. Временно можно задеплоить без `CLUB_CHAT_ID` — приложение заработает, но без проверки участников и постов.
- *Бот не пишет в группу (с `NOTIFY_GROUP=1`).* В логах `group announcement failed`: `bot is not a member` — добавьте бота в группу, `not enough rights` — дайте ему право отправлять сообщения. Книга или отзыв при этом всё равно сохраняются.
- *Ошибка про `--concurrency`.* Запустите с `CONCURRENCY=1 ./deploy/yandex-cloud.sh`.
- *Приложение отвечает 500.* Логи: консоль → Serverless Containers → `bookclub` → Логи. `AccessDenied` от бакета — у сервисного аккаунта нет роли `storage.uploader`.
- *Токен бота в переменных окружения* виден всем, у кого есть доступ к каталогу. Если это важно, перенесите его в Lockbox (флаг `--secret` у `revision deploy`).

**Восстановить данные.** В консоли откройте бакет → `backups/` → скачайте копию нужного дня. Каждая копия — состояние на начало дня, до первого изменения. Загрузите её в корень бакета под именем `bookclub.json`; экземпляры подхватят её за несколько секунд.

### Как приложение работает с несколькими экземплярами

Serverless Containers могут держать несколько экземпляров одновременно, и у каждого своя копия данных в памяти. Поэтому:

- каждое сохранение идёт с `If-Match: <ETag>` той версии документа, от которой считалось изменение;
- если другой экземпляр успел сохранить раньше (`412`), хранилище перечитывает документ, заново применяет изменение и повторяет запись — до 5 раз;
- чтение раз в 3 секунды проверяет, не изменился ли документ, условным `GET` с `If-None-Match` — если нет, бакет отвечает `304` без тела.

Две участницы, оставившие отзыв в одну секунду через разные экземпляры, получат оба отзыва. Это покрыто тестами в `internal/store/bucket_test.go`.

## Деплой на свой сервер

Нужен сервер, доступный в России без VPN, и HTTPS. Без `DATA_BUCKET` данные хранятся в файле.

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o dist/bookclub ./cmd/bookclub
```

Бинарник запускайте через systemd, HTTPS отдайте Caddy — он сам получает сертификат. Весь `Caddyfile`:

```
club.example.ru {
    reverse_proxy 127.0.0.1:8080
}
```

Или в Docker (после сборки бинарника):

```bash
docker build --platform linux/amd64 --provenance=false --sbom=false -t bookclub .
docker run -d --restart unless-stopped -p 127.0.0.1:8080:8080 \
  -v bookclub-data:/home/nonroot/data \
  -e BOT_TOKEN=... -e CLUB_CHAT_ID=... \
  bookclub
```

Бэкап — копия `bookclub.json` раз в сутки (cron + `cp`). Файл пишется атомарно, копировать его можно в любой момент.

## Решения, на которые стоит посмотреть на ревью

- **Ноль зависимостей.** Роутинг на `net/http` из Go 1.22 (`GET /api/books/{id}`), логи на `log/slog`.
- **JSON вместо БД.** Клуб — это сотни записей в год. `mutate()` меняет копию данных, сохраняет её и только потом подменяет состояние в памяти: упала запись — ничего не изменилось. Сохраняет бэкенд: файл (temp + fsync + rename) или бакет (условный PUT по ETag, см. выше). Хранилище спрятано за интерфейсом `api.Store`: SQLite или YDB подключаются новой реализацией без правок в хендлерах.
- **Бакет без SDK и ключей.** Object Storage принимает IAM-токен в `Authorization: Bearer`, а контейнер получает токен своего сервисного аккаунта у сервиса метаданных. Поэтому нет ни подписи запросов SigV4, ни статических ключей, ни внешних зависимостей.
- **Аутентификация.** Фронт шлёт `Authorization: tma <initData>`, сервер проверяет HMAC и срок давности. ID других участников наружу не отдаются, только имена.
- **Членство без Bot API.** `chat_instance` и `chat_type` входят в подписанную initData, поэтому сравнить `chat_instance` с ID группы клуба надёжно и не требует обращения к Telegram. Каждый новый `chat_instance` один раз пишется в лог (`opened from chat`), так его и находят для настройки.
- **Администраторы из env, а не из Telegram.** Брать админов группы через `getChatMember` (статус `administrator`) было бы удобнее, но Bot API из Yandex Cloud обычно недоступен — тогда пропали бы и права. Список в `ADMIN_IDS` работает без сети. Без него приложение ведёт себя как раньше: все равны, встречи назначает любой.
- **Членство в группе.** Ответ `getChatMember` кэшируется: «да» на 10 минут, «нет» на 1 минуту. Если Telegram недоступен, используется последний известный ответ. Ошибки чистятся от URL, потому что в нём токен бота.
- **«Поделиться» вместо постов бота.** Ссылка `t.me/share/url` открывает выбор чата в Telegram самого участника, серверу Bot API не нужен. Автопосты бота (`tg.Announcer`) остались как опция для сервера с доступом к Telegram.
- **Посты бота синхронно.** `sendMessage` вызывается в хендлере после сохранения и до ответа, с таймаутом 4 с. Не в горутине: Serverless Containers может заморозить экземпляр сразу после ответа, и пост бы потерялся. Ошибка Telegram только пишется в лог, книга или отзыв уже сохранены. Новый отзыв отличается от правки по `CreatedAt == UpdatedAt`; при повторе сохранения на `412` пост всё равно один, потому что он уходит после `mutate()`. Текст без `parse_mode` (название со `*` ничего не сломает) и обрезается до лимита Telegram в 4096 символов.
- **Фото: сначала файл, потом ссылка на него.** `PUT /api/books/{id}/cover` загружает фото на Диск под новым именем `<id книги>-<случайное>.jpg` и только потом записывает имя в книгу. Не загрузилось — у книги остаётся старое фото; не сохранилась книга — загруженный файл удаляется. Старый файл стирается последним: если это не удалось, на Диске остаётся лишний файл, но книга не показывает пропавшее фото. Формат проверяется по байтам (`http.DetectContentType`, только JPEG/PNG/WebP), а не по заголовку от клиента, поэтому SVG со скриптом не пройдёт.
- **Фото только участникам.** `<img src>` не умеет передать данные входа Telegram, поэтому фронт скачивает обложку через `fetch` с заголовком и показывает её из `blob:`. Имя файла входит в URL (`?v=…`) и меняется с каждым новым фото, так что ответ кэшируется в телефоне навсегда (`private, immutable`). В сервере — LRU-кэш на 16 МБ: каждая обложка скачивается с Диска один раз на экземпляр, а не при каждом показе. В списке обложки грузятся, только когда до них доскроллили.
- **Сжатие на телефоне.** Фото с камеры весит 3–10 МБ, а Serverless Containers принимает запросы до 3,5 МБ. Фронт уменьшает фото на `canvas` до 1280 px и JPEG 85% — заодно пропадают EXIF с геолокацией. Сервер всё равно режет тело на 3 МБ.
- **Диск без SDK.** REST API Диска: `GET /resources/upload` выдаёт одноразовую ссылку, файл идёт `PUT` по ней уже без токена. С доступом только к папке приложения токен не видит остальной Диск. Папка создаётся при первой загрузке.
- **Фото отзыва — то же хранилище.** `PUT /api/reviews/{id}/photo` повторяет порядок обложки (`uploadPhoto` и `servePhoto` общие), имя файла `<id отзыва>-<случайное>.jpg`. Фото не меняет `UpdatedAt`, поэтому отзыв не помечается «изменён»; правка текста фото не трогает. При удалении отзыва или книги файлы удаляются (у книги — сначала собираются фото её отзывов).
- **Превью через Яндекс Диск.** Робот превью Telegram не достаёт до Yandex Cloud (как и сервер до `api.telegram.org`), а страницы Диска читает. Поэтому превью строится по публичной ссылке Диска (`PUT /resources/publish`, затем `public_url`). Публикация ленивая — при открытии автором страницы книги, — и ссылка хранится в `Book.CoverLink` / `Review.PhotoLink`; новое фото сбрасывает её. После ошибки публикации сервер 5 минут не пробует снова, чтобы страница не ждала ту же ошибку при каждом открытии.
- **Своя страница превью — запасной путь.** Публичная страница `/s/<id отзыва>-<HMAC>` — единственное, что сервер отдаёт без входа. Ключ — `sha256` от токена бота, поэтому одинаков на всех экземплярах и не требует нового секрета; смена токена делает старые ссылки недействительными (пропадёт только превью). Редиректа в приложение нет: открытое из браузера приложение не получает `chat_instance` группы и отказывает в доступе. `?v=` в ссылке меняется с фото, потому что Telegram кэширует превью по URL; расширения `.jpg` в конце нет, чтобы ссылку не приняли за картинку.
- **XSS.** Фронт кладёт пользовательские данные в DOM только через `textContent` (функция `h()`), сервер принимает ссылки только `http(s)`.
- **Старшее поколение.** Шрифт 18px, кнопки от 52px, подписи словами, а не иконками. Подтверждения через нативный диалог Telegram, системная кнопка «Назад». Случайное закрытие свайпом отключено.
